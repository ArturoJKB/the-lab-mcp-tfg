\section{The recorded evidence base}
\label{sec:evidence}

Before presenting the claimed results, is good to state that every number reported in this chapter traces to one of the persisted run directories under \texttt{runs/}, and the charts below were generated from those same manifests, the context the system itself produced, not hand-built summaries. Two results deserve interpretation. First, the \emph{before/after} of the cleaning policy. A first run with naive one-hot encoding of the raw dataset (501 ticker dummies among others) produced a 22~GB intermediate CSV. The second run with the cardinality-aware policy produced 16--21~MB for the same data. A notably huge difference that turned a non working run into a 6-second succesfull one.Second, the leakage study. The naive feature set scored 84.2\% accuracy, but that number does not hold up in the real world. When the features are limited to those available at decision time, the score drops to 60.3\%, which is realistic for analyst ratings. Both runs are kept as inspectable evidence, and that is exactly the value of recording every rejection and every provenance detail.

The first test used three datasets whose column names explain themselves (sepal length, Balance, Age). With the EDA summary the agent verified every claim it made. Without any context it also verified every claim, because a model that is told nothing can still read the column names and guess correctly when the names describe the data. On these schemas the instrument could not separate the two arms, so we treat this table as a designed null. It motivated a second test on a dataset where column names hide their meaning.

That second test ran on the raw S\&P~500 file, before any cleaning. It has 18 columns with jargon names such as \texttt{from\_grade} and \texttt{price\_target\_action}, no documentation, and a five-class target called \texttt{action}. The grounded arm received a short EDA summary of the real file. The ungrounded arms received either nothing at all or only the domain (a financial table), so any claim they made about columns or classes was a guess.

Three findings. First, the role-specialized team completed every round it attempted at validity 1.0 and drove the absorbed champions (better score than baseline) of titanic, california-housing, and churn. Second, the single shared-prompt control never reached agentic mode. With \texttt{llama} or \texttt{mistral} as the shared prompt, the FeatureEngineer stage produced no sandbox-valid code, and the round fell back to the deterministic path. We then ran the control again with \texttt{GLM}, the one model that can write factory-safe transforms. Even \texttt{GLM}, broke every stage contract under the shared prompt, and the round degraded to deterministic. Third, the human cost is exactly one recorded gate decision per round, on the record. Across 53 recorded rounds there was one gate decision per round, zero bypasses, and 10 proposal rejections recorded across the project.

Two secondary findings complete the picture. On the imbalanced HR dataset (an 84/16 split) both the agent and the deterministic pipeline optimized accuracy, where the baseline model was already near its ceiling. The real headroom was in macro-F1, which ranged from 0.61 to 0.74 across the recorded runs. On this dataset the gap is a selection-policy gap, not a model-capability gap. And on california-housing the \texttt{gemini-lite} transform was safe but quality-degrading, with test $R^2$ dropping from 0.823 to 0.533, recorded as an honest no-absorption.

The loop is a ratchet (protocol in Section~\ref{sec:exp-kaggle}). The deterministic baseline is the bar each generation must beat, absorbed champions raise it, and the absorption gate (exact factory replay) is what separates a verified improvement from an anecdote. The Arm A comparison shows that the agentic round beat the deterministic baseline on 4 of the 6 recorded datasets (churn +0.95 pts, california-housing +2.21 pts, titanic +5.03 pts, S\&P +0.16 pts), tied on 2 (HR attrition after the try-all baseline itself improved to 0.8707; e-commerce at a computed-column ceiling of 1.0000 where headroom is definitionally zero), and trailed on none. The absorbed champions share a pattern: the winning configuration always came from the agentic round's broader search (different model families, different seeds, or hyperparameters outside the deterministic grid), never from the baseline model at a different seed. On the absorbed datasets, the factory replay confirmed that the agentic win was real and reproducible, not a seed artifact.

\textbf{The ratchet scoreboard.} The recorded ledgers of the experiment recorded \textbf{10 datasets}, \textbf{37 agentic generations}, \textbf{53 training rounds}, and \textbf{19 absorption events}, each replay-verified through the deterministic factory with exact metric equality before absorption. These resolve to \textbf{17 distinct champion models} (two absorbed configurations were superseded within their generations by later, stronger absorptions), and \textbf{6 honest refusals} (ties and below-baseline rounds that the absorption gate refused to ratchet).

\subsection{GLM-uniform control test: validator as capability enabler}

A GLM-uniform control test with the constant-feature validator and rewrite loop answered it. The round completed fully agentic at \textbf{validity 1.0 (12/12 trained, 392 s)}, with no absorption (best 0.7374 vs.\ baseline 0.8045.. The validator + repair loop was what made the reasoning model factory-safe,not the mixed-team brief. Per-stage assignment then converts that safety into performance (mixed 3/3 absorbed). Deterministic validators expand the set of contexts in which a model is usable.

\section{Agent case study: IBM HR attrition}
\label{sec:casestudy}

To show the pieces working together, this section documents a real recorded session with the grounded chat agent on the IBM HR attrition dataset (1{,}470 $\times$ 35, attrition rate 16.1\%). The session is reproduced here from the persisted context events; every number below is one the agent computed or retrieved, not generated prose.

\textbf{Step 1: Grounded exploration.} Asked what would be interesting to study, the agent pulled the context pack (identifying the dataset from its Kaggle documentation, including the ordinal scales stored as bare integers), ran the deterministic EDA (zero missing cells across 1{,}470 $\times$ 35; class balance 1{,}233 No / 237 Yes), and executed sandboxed pandas code to verify leakage suspects: three constant columns and a per-row-unique \texttt{EmployeeNumber} id. Its recommendations matched classic attrition analysis, focusing on recall/PR-AUC rather than accuracy given the 5.2:1 imbalance.

\textbf{Step 2: Evidence-based signals.} Over several \texttt{run\_python} calls the agent computed the signals it reported. Attrition rates by overtime (30.5\% with vs.\ 10.4\% without), by job role (Sales Rep 39.8\% vs.\ Manager 4.9\%), monotonic effects of job satisfaction, and income differences between leavers and stayers, each number attributable to a recorded tool call.

\textbf{Step 3: Grounded memory.} Asked to check prior work, the agent searched the context store and found two completed runs on the same dataset. Reporting their metrics, test accuracy-0.840 with a
0.557--macro-F1 (flagged by the agent itself as likely minority-class weakness) and 0.861 / 0.679 respectively. Correctly refusing to claim knowledge the manifests did not expose (``the run summaries don't expose the algorithm names, so I can't tell you which models these were'').

\textbf{Step 4: Proposal inside the boundary.} The agent drafted an experiment proposal. Its first attempt included \texttt{gradient\_boosting}; validation rejected it as unsupported in this factory's registry, and the agent corrected the proposal and resubmitted, a small but exact illustration of validation-as-feedback rather than validation-as-obstacle. The final proposal (logistic regression + random forest, seeds 42 and 7, constants and id dropped, stratified splits) was left \emph{awaiting human approval}, with the agent stating: ``I don't train anything myself, this proposal sits ready, and the deterministic pipeline only executes after you approve it.''

\textbf{Step 5: Honest tool failures.} The session's tool trace also records failures: two \texttt{run\_python} errors (one sandbox block: the agent rewrote its code without the blocked construct; one attempt to address a proposal through the wrong surface) and one proposal-validation \texttt{ValueError} with the full Pydantic message. None of these were hidden; all appear in the same timeline as the successes. The first of those failures presented a genuine finding, the sandbox's originally blocked lambda expressions, a incompatibility between AST-level policy and pandas-idiomatic code generation, resulting in not usable code. After the experiemnt it was safely lifted and repaired.  (Section~\ref{sec:exp-agentic-results}).

Two properties of this harvest matter for the thesis. First, it is \emph{deterministic}. The same script over the same evidence produces the same tickets, each backed by run identifiers. Second, the majority of the by-design findings are the safety rails working as intended (constant columns, scale guards, path safety, task-aware selection), which converts what a naive reading would call "errors" into a demonstration of the rejection-as-first-class design.
